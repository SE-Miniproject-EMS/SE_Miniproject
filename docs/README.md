# Project documentation

This directory contains the project's requirements, design, implementation, testing, and project-management evidence.

## Documentation map

| Area | Contents |
|---|---|
| [Architecture](architecture/) | Software architecture document, API reference, architecture/NFR assessment, implementation baseline |
| [Requirements](requirements/) | Software Requirements Specification and functional/non-functional traceability |
| [Testing](testing/) | Test plan, API integration test report, and consolidated testing results |
| [Project management](project-management/) | Team contribution evidence, sprint notes, and dated implementation plans |
| [Diagrams](diagrams/) | Editable Graphviz sources, diagram-generation scripts, and rendered diagrams |

## Issue-specific evidence

Issue-specific reports and supporting benchmark/demo artefacts remain grouped by issue number or report topic in this directory. Keep raw benchmark outputs alongside their associated issue evidence; summarize their meaning in the corresponding report rather than treating raw output files as standalone documentation.

## Maintenance conventions

- Keep one authoritative copy of each maintained document.
- Use descriptive filenames and preserve issue numbers where they provide traceability.
- Update this index when adding a new documentation area.
- Keep editable diagram source files beside their rendered output.
- Do not commit secrets, local databases, or temporary build files.

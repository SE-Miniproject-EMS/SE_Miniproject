# Functional Requirements and Traceability Matrix

**Issue:** [#22 — Define and document Functional Requirements (FRs)](https://github.com/SE-Miniproject-EMS/SE_Miniproject/issues/22)
**Reviewed baseline:** `main` at `7f9792c37df7d646e327eb2e2cdfffaf3f1d7682` (11 November 2026). Functional statuses below reflect merged PRs #47, #48, #51, #52, #53, #54, #55 and #56; benchmark/deployment/third-party limits are kept explicit.
**Purpose:** Map every requirement in the SRS to its backlog issue, implementation evidence, and a repeatable verification approach. Status describes the reviewed repository baseline, not unmerged feature branches or future plans.

## Status definitions

- **Implemented:** The reviewed source contains the required behavior and relevant tests/evidence.
- **Partially implemented:** Some behavior exists, but at least one explicit part of the requirement is missing or unverified.
- **Planned:** No implementation is present in the reviewed baseline; work is represented in the backlog.
- **Not verified:** A target is documented, but the repository does not contain sufficient runtime/deployment evidence to claim it is met.

## Implementation gap register

1. **Registration exists with limits.** Free-event registration, waitlisting, cancellation, FIFO promotion, token check-in and feedback APIs exist. Mock paid checkout/refund is present but not real-provider processing. External notification delivery, QR camera/scanner UI, feedback prompt UI, dashboards/CSV and the measured 500-attempt registration target remain gaps.
2. **Payment provider is not configured.** PR #48 is a mock simulator only; REQ-15–REQ-17 and NFR-SEC-02 need a selected provider, sandbox credentials, signed callback verification and provider-backed refund tests.
3. **Notifications need an external delivery adapter.** REQ-18–REQ-20 require configured email/SMS credentials or a documented test double. Account-verification console output does not satisfy event notifications.
4. **QR check-in has a token-backed API but no scanner UI.** REQ-21–REQ-23 have token/check-in behavior; a QR image/camera workflow remains a UI gap.
5. **Reporting is a separate backlog item.** REQ-24–REQ-26 are not delivered merely because an ADMIN role exists.
6. **Feedback backend exists but the full prompt/display UI is incomplete.** REQ-27–REQ-28 use checked-in attendee eligibility and organizer-scoped API access; finish/verify the user-facing feedback prompt and display.
7. **Non-functional targets require evidence.** A local event-list benchmark does not establish 500-registration concurrency, production uptime or horizontal scalability.
8. **Email verification is development-only for delivery.** Verification logic exists, but a real email provider is not configured in the reviewed baseline.
9. **SRS count mismatch:** Issue #22's description says “REQ-1 through REQ-34”, but the SRS Appendix C traceability table contains 38 rows: REQ-1–REQ-28 plus 10 NFR IDs (NFR-PERF-01/02, NFR-SEC-01–04, NFR-USAB-01, NFR-REL-01, NFR-MAINT-01 and NFR-SCAL-01). This matrix preserves all 38 entries from the SRS table rather than silently dropping four NFRs.
